# ynh v0.18.2

## A harness's permission level

A session that runs with nobody to approve (a delegate session, `ynh run <id> -- "<task>"`, and
`ynh agent run --harness`) now opens at the harness's **permission level**: `none`, `edits` or `all`,
the same on every vendor ([ynh #1058](https://github.com/eyelock/ynh/issues/1058)). Until now it got
each vendor's headless default: no shell on Claude Code, everything on Copilot CLI, read-only on
Codex. See [Permission levels](../permission-levels.md).

### What changes for a harness you have already accepted

**An accepted harness now opens at `all` on its next one-shot run, with no new acceptance.** A harness
that declares no level opens at `all` once accepted, and an acceptance made before v0.18.2 still
holds, because an undeclared level is not part of what was accepted. That includes a delegate session
and an `ynh agent run --harness` worker, which before v0.18.2 got no permission flag unless you passed
`--auto-approve`.

Run these only inside containment you own (a container, an egress policy, a review of what lands), or
narrow them.

### How to narrow

- In the harness: `"auto_approve": "edits"` or `"none"` at the top of its manifest. This is its
  ceiling.
- In a parent: `"auto_approve"` on a `delegates_to` entry narrows that delegate.
- For one run: `ynh run <id> --auto-approve edits -- "<task>"`, or `ynh agent run --auto-approve`. On
  an interactive run, `ynh run <id> --auto-approve <level>` caps every delegate the session starts.

A level only narrows: a wider request is refused before the session starts. Declaring or changing a
level means accepting the harness again. `ynh trust show`, `ynh info` and `ynh ls` show the level and
where it comes from.

### Per vendor

Each level is held exactly with the vendor's own setting, or refused at start, never widened. `edits`
is refused on Codex and Cursor, which have no mode that approves edits but not commands; `none` is
refused on Cursor. On Claude Code, `edits` is `acceptEdits` with the `Bash` tool withheld. The full
table is in [Permission levels](../permission-levels.md#what-each-vendor-is-passed).

### Other changes

- **Accepting a parent accepts its whole delegate tree.** `ynh trust accept <parent>`, `ynh install
  --trust` and `ynh run <folder> --trust` accept every `a2a` delegate below the parent, nested ones
  included, each under its own id at its pinned commit, installing one that is not installed. What
  each runs is shown first, and it is all or nothing: if one cannot be accepted, nothing is recorded,
  the parent included. A change to one delegate re-gates only it. `ynh trust` shows a delegate accepted
  this way as `with <parent>`. [Trust a delegate](../how-to/trust-a-delegate.md).
- **`--trust` needs the whole tree pinned.** `--trust` refuses any `a2a` delegate in the tree, nested
  ones included, whose `ref` is not a full 40-character commit SHA, naming the delegate that declares
  it, as it already did for includes and native delegates. `ynh update --trust` and `ynh include ...
  --trust` refuse a floating `a2a` entry of the harness too; they accept the harness itself, not its
  delegates.
- **An image of a harness with no commands needs acceptance.** `ynh image` of an unaccepted harness
  that runs no commands is refused, because the image runs one-shot: "refusing to build an image of
  <id>: you have not accepted it. It executes no commands, but the image runs one-shot, and a one-shot
  run opens at all with nobody to approve (default)."
- **A one-shot run needs acceptance even with no commands.** `ynh run <id> -- "<task>"` and `ynh agent
  run` of a harness that runs no commands are refused until it is accepted; interactive runs of it
  still need none.
- **A one-shot folder run.** `ynh run <folder> --trust -- "<task>"` opens at the folder's level on every
  vendor, Copilot CLI included; without `--trust` a one-shot folder run is refused, naming `--trust`.
- **Claude Code as root.** A Claude Code run at `all` as root is refused before Claude starts, naming
  the fixes: a non-root user, ynh's image, `--auto-approve edits`, or `IS_SANDBOX=1` (or
  `CLAUDE_CODE_BUBBLEWRAP`) in a container that is the sandbox. See
  [Run a harness on CI](../how-to/run-a-harness-on-ci.md#run-as-a-non-root-user).
- **One-shot Claude Code runs are read as a stream.** ynh passes `--output-format stream-json` and
  checks the mode the session opened in. **A script that passes its own `--output-format` (or
  `--input-format`) to a one-shot Claude Code run is now refused**: remove it. A session whose hooks
  are switched off (`disableAllHooks`, or by policy) is stopped, because the check could not run, and a
  stopped run exits nonzero. [Permission levels](../permission-levels.md#the-mode-a-session-opened-in).
- **The project's mode.** When the working folder's `.claude/settings.json` or `.codex/config.toml` sets
  a narrower mode, a run opens at it and prints a line naming the file. Before, `ynh agent run` refused.
